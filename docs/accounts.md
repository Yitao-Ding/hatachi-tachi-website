# 引き継ぎ資産一覧

運営が毎年二十歳の代に総入れ替えする前提のプロジェクト。
**サービスの所有アカウントを個人名義にすると、2〜3年後に誰も触れなくなる。**
Phase 4 (デプロイ・ドメイン取得) に入る前にここを決めること。

学生団体の公式サイトが消える一番多い経路は、当時の代表の個人アカウントにドメインとホスティングが載ったまま卒業し、自動更新が止まってドメインが失効する、という流れ。移管は後からやるほど手間が増える (レジストラ移管・Vercel プロジェクト移管・GitHub リポジトリ移管は、いずれも元の所有者本人の操作が必要)。

## 決めること

| サービス | 用途 | 推奨 | 現状 |
|---|---|---|---|
| microCMS | 記事・アーカイブの更新 | 団体共通メールで作成 | 未作成 |
| GitHub | ソースコード | 団体の Organization を作り、その配下に置く | ローカルのみ (未 push) |
| Vercel | ホスティング | 団体共通メール。Hobby でも Team は作れる | 未作成 |
| ドメインレジストラ | 独自ドメイン | 団体共通メール + 団体の支払い手段 + 自動更新ON | 未取得 |
| Google アカウント | 上記すべての受け皿 + 問い合わせメール | 団体共通のものを1つ作る | — |

## 代替わりのときにやること

1. microCMS のメンバーを入れ替える (無料枠は3人まで。旧メンバーを削除してから新メンバーを招待)
2. GitHub Organization のメンバーを入れ替える
3. Vercel のメンバーを入れ替える
4. ドメインの支払い手段が生きているか確認する
5. この表の「管理者」を更新する
